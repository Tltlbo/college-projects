## 1. ⚙️ 리눅스 커널 디바이스 드라이버 기반 IoT 펌프·모터 제어 시스템

> 라즈베리파이 리눅스 환경에서 물리 GPIO 레지스터를 직접 매핑·제어하는 캐릭터 디바이스 드라이버(Kernel Module)를 구현하여 다중 펌프 및 교반 모터를 정밀 구동한 IoT 프로젝트

- **폴더 위치**: [`./리눅스-커널-드라이버-펌프-모터-제어`](./리눅스-커널-드라이버-펌프-모터-제어)

### 🗓️ 개요

- **구분**: 학부 IoT 프로젝트
- **역할**: 리눅스 커널 모듈(`pump_driver`, `motor_driver`) 개발 및 User Space 제어 애플리케이션 구현
- **기술 스택**: `C`, `Linux Kernel Module` (`linux/module.h`, `linux/fs.h`, `linux/io.h`), `Raspberry Pi (BCM2837 GPIO)`, `Character Device Driver`, `System Call` (`open`, `write`, `close`)

### 🚀 주요 기능

- **캐릭터 디바이스 인터페이스 제공**: 리눅스 커널 공간(Kernel Space)에 캐릭터 디바이스 드라이버(`/dev/pump_driver`, `/dev/motor_driver`)를 등록하고 VFS(Virtual File System) 기반 파일 I/O 인터페이스 제공
- **Memory-Mapped I/O 기반 GPIO 제어**: 물리 메모리 주소(`GPIO_BASE: 0x3F200000`)를 커널 가상 주소로 매핑하여 **GPIO 17번(펌프 모터)** 및 **GPIO 19번(교반 모터)** 핀의 입출력 모드와 출력 레벨 직접 제어
- **시간 지정 자동 제어 프로그램**: 사용자 공간(User Space) 실행 인자(`<time>`)로 전달된 시간(초) 동안 펌프 및 모터를 작동시킨 후 자동 정지하거나 주기적으로 ON/OFF를 수행하는 제어 프로그램 구동

### 🙋‍♂️ 핵심 구현 내용

- **캐릭터 디바이스 드라이버 설계 및 등록**
  - `register_chrdev()`(Major 번호 `221`)와 `struct file_operations`(`.open`, `.write`, `.release`) 구조체를 정의하여 User Space와 Kernel Space 간 시스템 콜 인터페이스 구축
- **Memory-Mapped I/O 및 비트 마스킹을 통한 레지스터 직접 제어**
  - `ioremap(GPIO_BASE, GPIO_SIZE)`을 사용해 물리 GPIO 레지스터를 커널 가상 주소 공간에 매핑하고, 컴파일러 최적화로 인한 레지스터 접근 누락을 방지하기 위해 `volatile unsigned int *` 포인터로 선언
  - `GPFSEL1` 레지스터(`pump + 1`, `motor + 1`)에서 인접 핀 설정을 보존하기 위해 `&= ~(0x07 << (3 * N))`으로 대상 핀의 3비트를 `000`으로 초기화한 뒤, `|= (0x01 << (3 * N))` 연산으로 안전하게 Output 모드(`001`) 설정
- **User-Kernel 데이터 교환 및 하드웨어 리소스 보호**
  - `copy_from_user()`를 통해 User Space의 1 Byte 제어 명령을 안전하게 커널 버퍼로 복사한 뒤 `GPSET0`(`+ 7`, HIGH 출력) 및 `GPCLR0`(`+ 10`, LOW 클리어) 레지스터 조작
  - `pump_usage` / `motor_usage` 플래그를 통해 다중 프로세스의 동시 접근 시 `-EBUSY`를 반환하여 경합을 방지하고, `.release` 시 `iounmap()`을 호출하여 커널 메모리 누수 방지

### 🧩 기술적 도전 & 해결

- **문제**: User Space 애플리케이션에서 하드웨어 물리 주소(`0x3F200000`)에 직접 접근할 수 없으며, 같은 기능 선택 레지스터(`GPFSEL1`)를 공유하는 다른 GPIO 핀들의 설정 비트가 덮어써질 위험 존재
- **해결**: `ioremap()`을 통해 커널 가상 주소 공간으로 매핑한 뒤, 대상 핀의 3비트 영역만 `AND(&= ~)` 마스크로 `000` 초기화 후 `OR(|=)` 연산으로 `001`(Output)을 설정하여 주변 핀의 비트 상태를 안전하게 보호

### 🌟 성과 및 배운 점

- 고수준 라이브러리에 의존하지 않고 BCM2837 데이터시트의 레지스터 맵(`GPFSEL`, `GPSET`, `GPCLR`)과 리눅스 VFS 계층을 직접 연결하며 운영체제 커널과 하드웨어 제어의 원리 체득

## 2. 🐧 리눅스 파일 시그니처(Magic Number) 기반 파일 타입 판별기

> 파일 확장자에 의존하지 않고 바이너리 헤더의 매직 넘버(File Signature)를 추출·비교하여 디렉토리 내 모든 파일의 실제 포맷을 판별하는 Linux 시스템 프로그래밍 도구

- **폴더 위치**: [`./리눅스-파일-시그니처-타입-판별기`](./리눅스-파일-시그니처-타입-판별기)

### 🗓️ 개요

- **기간**: 2022.11 (1인 개인 프로젝트)
- **역할**: 전체 설계 및 C 구현 (`main.c`, `signature.c`, `signature.h`, `Makefile`)
- **기술 스택**: `C`, `Linux System Call` (`lstat`, `opendir`, `readdir`, `S_ISREG`, `S_ISDIR`), `File I/O`, `Makefile`

### 🚀 주요 기능

- **다중 바이너리 시그니처 인식**: 외부 시그니처 데이터베이스(`file_sig_data`) 파싱을 통해 아래 6종의 바이너리 포맷을 확장자와 무관하게 판별
  - `7F 45 4C 46` → **Executable and Linkable Format (ELF)**
  - `89 50 4E 47 0D 0A 1A 0A` → **PNG**
  - `FF D8 FF E0` → **JPG**
  - `66 74 79 70 69 73 6F 6D` → **mp4**
  - `00 00 01 B3` → **mpeg**
  - `1F 8B` → **gzip**
- **단일 파일 및 디렉토리 재귀 탐색**: 명령줄 인자(`argv[1]`)가 단일 파일인지 디렉토리인지 판별하여, 디렉토리일 경우 하위 폴더까지 재귀 탐색하며 전체 파일의 실제 타입을 일괄 출력
- **사용법 및 지원 포맷 안내**: 실행 시 로드된 시그니처 개수와 지원 타입 목록을 출력하며, 인자 누락 또는 미존재 경로 입력 시 `Usage` 안내

### 🙋‍♂️ 핵심 구현 내용

- **시그니처 파서 및 정규화 로직 구현 (`main.c`)**
  - `strtok()`을 활용해 `file_sig_data`의 주석(`#`) 라인을 필터링하고, `|` 구분자로 매직 넘버와 파일 타입 분리
  - 공백으로 구분된 16진수 시그니처 문자열(예: `7F 45 4C 46`)을 연속된 문자열(`7F454C46`)로 정규화하여 구조체 배열(`Sig sigs[]`)에 적재
- **시스템 콜 기반 디렉토리 재귀 순회 구현 (`signature.c`)**
  - `lstat()`의 `st_mode` 매크로(`S_ISDIR`, `S_ISREG`)와 `opendir()` / `readdir()`를 결합한 재귀 함수 `isdir()` 구현
  - 현재 디렉토리(`.`) 및 상위 디렉토리(`..`) 엔트리를 필터링하여 무한 재귀 루프 방지
- **바이너리 헤더 16진수 추출 및 매칭 (`main.c`, `signature.c`)**
  - 대상 파일을 바이너리 읽기 모드(`"rb"`)로 열어 초기 바이트를 `fgetc()`로 추출하고 `sprintf("%X")`로 16진수 문자열 변환 후 `strstr()`로 시그니처 매칭
